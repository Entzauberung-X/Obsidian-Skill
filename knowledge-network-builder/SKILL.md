# 从零搭建 STEM 知识网络（knowledge-network-builder）

> 本技能把「**从零学一个新领域**」变成可执行、可增量、可检验的五阶段流水线，产物是一张**知识网络**——不是笔记堆。
> 知识网络 = **三色卡片（节点）× 类型化关系（边）**，由一张 hub 总图统摄。每张卡都经过「第一性原理」解剖保证专业深度；每条指令都可单独小步执行，保证上手容易。
>
> 适用：任意 STEM 新领域（数学 / 物理 / 控制 / 信号 / ML / CS / 机器人 / 电路 / 三维重建……）。
> **完成标准 = 搭建起知识网络**：学科地图完整、依赖有序、核心概念卡齐、空白被显式列出、关键概念能降维讲清。
> 不负责：刷题、考试冲刺、逐章精读并誊抄教材——那是各科目专项技能（book-note-organizer 等）的职责。

---

## 核心哲学：知识网络 = 节点 × 边 × 本质

> 学一个新领域，最终要的不是「看过的东西」，而是「一张能用来思考的网」：**每个概念是一个节点；每条「它和谁连着、怎么连着」是一根边；每个节点上用第一性原理写清「它为什么必须这样」。**

五条贯穿性原则（建每张卡、连每条边时自检）：

1. **本质优先**：每张卡先写「一句话定位」，把概念还原到「它解决什么问题」再展开；先本质，后操作。禁止以名词解释/流水账开头。
2. **三色卡为节点**：任何新知识点先分流成 🔴定义 / 🔵案例 / 🟢方法 之一再落卡。**分不清颜色的知识 = 还没懂**；犹豫时就问用户，不擅自归类。
3. **连边即理解**：单张卡不成立。每张卡必须 ≥2 条类型化出/入边；写不出它和谁连着，说明还没学到家。
4. **红色卡精确无模糊**：术语/公式定义不允许「大概、差不多」。公式给全**符号、量纲、成立条件**；推不出来、证不动就写「待重演」进 `## 待补充`，**不许假装懂**。
5. **活档案·可迭代**：疑问、顿悟、讲不清的地方全部留痕；网络随学习持续增删改边，不做一次性誊抄。同类疑问/顿悟积累 ≥3 条 → 升级为校验期的正式检查项或固化期专题。

## 卡片三色体系（节点类型）

> 三色 = 三类节点卡。**输入材料时给每个知识点「上色」**，颜色决定它长成哪种卡、写多深。
> 判断口诀：它是「**什么**」→ 定义卡；它「**长什么样 / 有什么现象/数据**」→ 案例卡；它「**怎么用 / 用什么视角看**」→ 方法卡。

| 色 | 卡类 | 记录什么 | 精确度要求 | 何时生成 | 文件命名 |
|:--|:--|:--|:--|:--|:--|
| 🔴 | **核心定义卡** | 领域独有术语、符号、公式的精确含义 + 成立条件 + 边界 + 易错 | **必须精确无歧义**（STEM：给全公式 + 量纲 + 条件） | 学到新术语/符号/公式 | `定义 · {名}.md` |
| 🔵 | **案例/现象卡** | 现实/实验/数值实例、具体数据点，让抽象落地 | 可复现，**必须标来源**（书章/论文/实验/课程/URL） | 遇到实例、现象、实验数据 | `案例 · {名}.md` |
| 🟢 | **方法论/视角卡** | 该领域分析问题特有的角度、套路、证明/估计方法 | 说清**适用条件 + 何时失效** | 学到一个方法/技巧/视角 | `方法 · {名}.md` |

**命名规则**：文件名**不用裸 emoji**（跨平台/检索安全），用中文词前缀 + ` · `；H1 标题带色 emoji（如 `# 🔴 定义 · 拉普拉斯变换`）。
**一义一卡**：建卡前先在主题目录与 hub 搜 basename——已有则**连边不重建**，防碎片。

### 三色通用写作纪律（STEM）

1. **公式释理**：能用一个公式/1–2 步推导讲清的事，不堆文字；核心公式一律 `$$\boxed{...}$$` 块，配符号说明。
2. **语言简洁**：删虚词口水句（可以/其实/也就是说）；能用表格就不写散文。
3. **本质 > 操作**：每节先讲「为什么」，再讲「怎么算/怎么做」。
4. **callout 克制**：只用 `[!abstract] 一句话定位`、`[!note] 理解 ·「口诀名」`、`[!warning]/[!danger] 易错`、`[!example] 案例`、`[!question] 待验证` 五类。
5. **不许编造**：蓝色卡的来源、实验数据、具体数值必须真实可查；拿不准标 `待验证` 并进待补充。

## 概念关系（边的类型化）

关系要**少而稳**，让 Obsidian graph 一望即知网络结构。统一写在各卡的 `## 概念关系`（或对应小节），方向即链接方向：

| 关系 | 记号 | 含义 | 写法示例 |
|:--|:--|:--|:--|
| 先修 | `←` | 要懂本卡先要懂它（决定学习顺序） | `先修：[[定义 · 矩阵乘法]]` |
| 推出 | `⇒` | 从本卡能推出的更强结论/兄弟概念 | `推出：[[定义 · 卷积定理]]` |
| 类比 | `≈` | 结构同构、可跨域迁移（深度引擎第⑤问的落点） | `类比：[[定义 · 卷积]]`（多项式乘法） |
| 落地 | `⌘` | 抽象→具体：被哪个案例/方法使用 | `落地：[[案例 · …]]` |
| 边界/反例 | `≠` | 什么时候不成立、和什么概念易混 | `边界：[[…]]` |

**铁律**：
- 每张卡 ≥2 条出/入边（含主题目录、hub 回链）；孤点卡不合格。
- 边的**方向朝被依赖/更基本**的一方；hub 只存「主题 ↔ 卡片」与「主题 ↔ 主题」的主干边，细节边都写在卡内。
- 想加新关系类型？先在 `00、知识网络 hub` 的 `## 待补充` 记一条，攒够 3 个真实需求再扩展，不预设花哨关系。

## 五阶段流程（核心工作流）

五阶段严格按 ①→⑤ 推进；③④⑤ 可循环（学新料回到③，定期④，关键概念过⑤）。每阶段给「目的 / 产出 / 步骤 / 指令」，**任何一步都可停下问用户，绝不批量连做多步**。

### 阶段① 骨架期 · 学科地图

- **目的**：先有整图再落点，避免学到哪算哪。
- **产出**：`01、骨架/01、学科地图.md` + hub 初始化。
- **步骤**：
  1. 问领域目标与边界 → 确定**该领域最本质的 5–9 大问题模块**（按「它要回答什么问题」切，不照抄教材目录）。
  2. 每个模块写**一行本质问题** + 一句话定位。
  3. 显式写「**不学什么**」边界，防止骨架无限膨胀。
  4. 在 hub 同步 `## 学科地图（总览）` 与 `## 学习进度` 空模板。
- **验收**：每个模块能答「学完它能回答什么问题」；模块数 5–9。
- **指令**：`建骨架：<领域>`、`加分支：<模块>`、`改边界：不学…`。

### 阶段② 排序期 · 前置依赖清单

- **目的**：给骨架定学习顺序；能复用旧知识就不重学。
- **产出**：`01、骨架/02、前置依赖.md`。
- **步骤**：
  1. 逐模块列出**前置概念/工具**。
  2. **先扫 Vault**：旧知识能 `[[wikilink]]` 挂接的标「已具备」并给出链接，不重造卡；缺的标「补给站」（一句话：要补到什么程度 / 推荐 5 分钟入门资料）。
  3. 拓扑排序 → 建议学习序 `A → B → C`（写进 hub `## 前置依赖总览`）。
  4. 补给站太多（>模块数）→ 提醒用户目标过大，建议缩边界或先单学一个模块闭环。
- **验收**：每个模块有前置列表；学习序无环。
- **指令**：`排顺序`、`加前置：<模块> ← <概念>`、`<概念> 我已会`。

### 阶段③ 血肉期 · 三色卡片输入（循环）

- **目的**：逐块吃材料，把新知识长成三色节点并连边——**知识网络长肉的阶段，也是主要循环**。
- **产出**：主题目录 + 三色卡片 + 边 + hub 进度更新。
- **步骤**：
  1. 读一小段材料（一节/一讲/一篇），**先问用户这一段想重点搞懂什么**。
  2. 把该段每个新知识点分流成 🔴/🔵/🟢（分不清就问用户）。
  3. 建卡（用上方对应模板），一义一卡；红色卡按「专业深度引擎」补第 1–3 问，推不动就 `待重演`。
  4. 连边：更新该卡 `## 概念关系` 与相邻卡；蓝卡必须链接 ≥1 张红卡，绿卡必须链接它用到的红/蓝卡。
  5. 更新 hub 进度 checklist + 主题目录。
- **小步纪律**：一次最多处理一个知识点/一张卡；用户说「继续」才做下一张。
- **指令**：`加卡片：{材料}`、`收 {书/章}`、`🔴 加定义：X`、`🔵 记案例：X`、`🟢 记方法：X`、`连边：X 是 Y 的先修`。

### 阶段④ 校验期 · 空白扫描 + 交叉认证

- **目的**：抓「以为自己会了，其实没学」的空白；给核心结论找独立依据。
- **产出**：`03、校验/01、空白扫描.md`、`03、校验/02、交叉认证.md`。
- **步骤（空白扫描）**：
  1. 拿 hub 学科地图**逐模块对照已有卡片**：缺的核心定义、没连的边、没落的案例 → 全列 `- [ ]` 缺口清单（不回填，先显式看见）。
  2. 有教材/考纲/大纲时，用它做第二份对照清单。
- **步骤（交叉认证）**：
  1. 每张**核心红卡**的 `认证` 从 `待交叉` 推进：找第二个来源（另一本书/论文），或**独立从第一性原理推导一遍**（「自证」算认证，但不算「多源」）。
  2. 认证结果写进 `03、校验/02、交叉认证.md` 表：`概念 | 来源1 | 来源2/自证 | 结论一致? | 状态`。
  3. 冲突不抹掉——两边都保留并标注，进该卡 `## 待补充`。
- **验收**：核心红卡无 `待交叉` 遗留（或全部显式进待补充）；缺口清单存在且可勾。
- **指令**：`空白扫描`、`交叉认证：X`、`网络健康检查`。

### 阶段⑤ 固化期 · 降维输出压力测试

- **目的**：用「能不能讲给小白」验证真懂；把长熟模块蒸馏成可速查的成品。
- **产出**：`04、固化/讲给小白 · X.md`；模块成熟后 `04、固化/{模块}速查.md`。
- **步骤（讲给小白）**：
  1. 对每张**必懂红卡**写：**本质一句话 → 一个生活类比 → 一个最小数字例子 → 3 个「如果…会怎样」追问并自答**。
  2. 通过标准：**不翻原卡能讲清**。卡住的地方 = 真空白 → 打回阶段④记缺口，并回卡内补。
- **步骤（模块速查）**：该模块卡片齐 + 大部分已认证后，蒸馏一张速查卡，**质量线参照 `考研/《信号与系统》（奥本海姆）/14、公式汇总/0、特殊函数.md`**：一句话定位 + `\boxed{}` 核心公式 + 属性/对比表格 + 易错提醒（❌/✅）+ `## 知识关联` 回链。
- **指令**：`降维输出：X`、`写速查：<模块>`、`自测追问：X`。

## 专业深度引擎（第一性原理 · 五问 + 重演法）

> 「专业深度」不靠多抄资料，靠**把每个概念解剖到能自我重建**。对任意 🔴 核心定义卡（及其公式），过下面五问；答不出的进 `## 待补充`，**不背过去**。

1. **它解决什么问题？**（没有它，前人会卡在哪一步？）
2. **它能从哪些更基本的东西推出来？**（动手试 1–2 步推导/证明，而不是抄定义。）
3. **它的边界在哪？**（成立条件、量纲、极限情形：把参数推到 0 / ∞ / 退化时还成立吗？）
4. **条件破坏会怎样？**（找反例/失效模式 → 沉淀为该卡「易错」或一张边界反例说明。）
5. **它与我已懂的什么同构？**（跨域类比：把这个结构映射到一个我熟悉的领域，找同构点——类比边 `≈` 的原料。）

**重演发现法（给五问供能）**：学习顺序的最终裁判不是教材目录，而是**该学科的发现史逻辑**——先有问题，再有工具，再有抽象。阶段②排序时，若 A 比 B 晚被发明、却先被写进教材，通常先学 A 的现象直觉再学 B 的抽象，或反之，要让用户知道两种读法的取舍。给依赖序时用「重演视角」解释一句「为什么这个顺序是自然的」。

**降维失败回流规则**：凡「讲给小白」卡住、或五问里第 2/4 问答不出，这不是失败，是**发现空白**——必须回流阶段④记缺口，并把「卡在哪」写进该卡待补充。**不许跳过并继续往下学。**

## 安全规则

❌ **禁止**：
- 修改受保护树：`raw/*`、`wiki/*`、`考研/*`、`0854/*`（及用户明确指定的其它只读区）。
- 用户领域与旧知识重叠时另起炉灶——Vault 已有该概念就 `[[wikilink]]` 挂接，**不重建**。
- 编造：蓝卡的来源/实验数据/数值、红卡的公式成立范围，拿不准标 `待验证`/`待重演`，**不许编**。
- 红色卡写模糊定义，或用口水话替换精确公式。
- 未经确认连续批量建卡/改多张卡（违背「小步增量」）。
- 替用户选择根路径或擅自创建文件夹结构。

✅ **强制**：
- 先问清领域/目标/路径再动手；路径下有旧笔记先读再挂接。
- 一义一卡；每卡 ≥2 边；每操作后更新 hub。
- 分不清三色就问，不擅自归类。
- 建卡前先查重（主题目录 + hub 搜 basename）。
- 每张红卡带「为什么必须这样」段；推不动就写 `待重演` 进待补充。
- 讲给小白卡住的点必须回流空白扫描，不许带病前进。
