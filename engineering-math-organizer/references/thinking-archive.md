# 数学笔记的本质：思维外化 · 活档案（工程数学适配）

> 核心定位：工程数学笔记的价值 = 每个数学工具在工程里"用来解决什么问题"，**且记录"我如何理解这条 数学→工程 的路"**。思维外化 = 把"数学如何被理解、被误用、被落到工程"外化成可追溯、可迭代的认知档案。它是思维发生的"第二次现场"：**写笔记 ≠ 搬运公式，写笔记 = 让"数学↔工程"的理解再发生一次。**

## 五条贯穿性原则（工程版）

| 原则 | 工程语境含义 | 落地 |
|:---|:---|:---|
| ① 思维外化，非知识搬运 | 公式/算法不只是抄，要记录"为什么用它解决这个工程问题" | 每条笔记含个人化理解（工程直觉/理解注释/顿悟） |
| ② 顿悟必留痕 | "原来这个公式在 XX 系统里是干这个的"是核心认知资产 | `> [!note] 顿悟 ·「...」` 或「思路轨迹」笔记 |
| ③ 错题归因到思维漏洞 | 从"工程误用/报错"反推"对数学的哪个理解有漏洞" | 「错题归因」笔记：误用分类 → 漏洞 → 对策 → 变式 |
| ④ 可追溯 | 数学→应用 双向追溯 + 理解轨迹 | 映射表 + "原来以为 X → 现在知道 Y" |
| ⑤ 活档案·可迭代 | 笔记随理解生长 | 待补充落实删行回链；同类沉淀升级 |

## 新笔记类型（模块内相对编号，子笔记规范）

### 类型：错题归因笔记 `NN、错题归因-{主题}.md`

**定位**：工程误用归因——应用数学工具时出错（公式/算法用错场合、建模对象选错、数值不稳定、概念混淆）。从"误用/出错"反推"对数学本质的理解漏洞"。

**工程误用分类**：

| 误用类型 | 判定标准 | 典型例子 |
|:---|:---|:---|
| 数学误用 | 公式/定理用错场合、符号错 | 把矩阵乘法当可交换、旋转矩阵方向记反 |
| 建模错误 | 对象/假设选错 | 忽略线性化前提、状态量选错坐标系 |
| 数值/实现错误 | 理论对，实现错 | 离散化步长过大导致发散、数值不稳定 |
| 概念混淆 | 两概念混为一谈 | 传递函数 vs 状态空间、滤波 vs 平滑 |

## 织入现有模板

1. **子笔记 → 多实现路径对比（一题多解工程版）**：同一数学问题用不同方法/算法路径，比较"本质同一性"与"工程适用边界"（精度/算力/鲁棒性）。
2. **理解注释 → 可含"理解轨迹"**：反直觉概念写"我原来以为 X → 实际上 Y"，正对应数学→工程的可追溯。
3. **待补充机制 → 迭代升级**：同类误用/顿悟沉淀 ≥3 条 → 升级为专题或并入相关应用模块子笔记；删待补充行、回链。

## 判断速查：算不算"思维外化"？

| ❌ 不是（搬运/废话） | ✅ 是（思维外化） |
|:---|:---|
| 抄公式/算法，无工程落点 | 公式 + 工程落点 + 我为什么这样理解 |
| "这里报错了" | 还原误用走向 + 归因到数学理解的漏洞 |
| "这个公式在 XXX 里很重要" | 顿悟：它在 XXX 里具体扮演什么角色 |
